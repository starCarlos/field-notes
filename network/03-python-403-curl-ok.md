# 同一个代理，Python 403、curl 正常：我放弃了修根因

> 2026-11-21｜个人实测记录
> 素材：个人实测记录

---

一台机器、一个代理、一个 key。curl 能把文件传上去，Python 一律 403。

最后我没修 Python，改成 `subprocess` 调 `curl.exe`。脚本跑完了，1.5 万字到手。

这篇文章记录完整排查过程，**包括我没查出来的那部分**。

## 要干什么

一段 77 分钟的课堂录屏，要转成逐字稿。

本地没有能跑得动的 GPU，所以用 Groq 的 `whisper-large-v3`——按音频时长计费，一节课的量级可以忽略。出口要过本地的 clash 代理。

看起来是十分钟的活。

## 坑一：配置里的端口早就换了

`config.py` 里写着 `127.0.0.1:7xxx`。

照抄，连不上，ECONNREFUSED。

实际监听的是另一个端口（记作 `7yyy`）。`7xxx` 那个端口早就没人用了，配置没跟着改。

这个坑没有技术含量，但它是第一个耗时间的地方。**教训只有一句：别信配置文件里的端口，先验一次。**

```
curl -x http://127.0.0.1:7xxx https://api.ipify.org
```

能返回 IP，才说明代理通。

## 坑二：urllib 403，curl 正常

端口改对之后，真正的怪事来了。

同一个 URL、同一个 key、同一个代理、同一个文件：

- `curl.exe -F file=@xxx` → 200，返回 JSON
- `urllib.request` → 403

第一反应是 key 有问题。换了一个 key，一样 403。同一个 key 用 curl 又是 200。

第二反应是 endpoint 或参数拼错。把 curl 的参数逐个对到 urllib 里，还是一样。

第三反应是代理只放行 curl。但代理是本地 clash，不认客户端，这个假设不成立。

到这里可以确定：**不是网络问题，不是凭证问题，是客户端本身的差异。**

## 三个候选解释（都没验证）

1. **TLS 指纹**。Python 的 OpenSSL 栈和 curl 用的 TLS 栈不同，握手时的 JA3 指纹不一样，有些网关会直接拦。
2. **默认 UA**。`urllib` 默认的 User-Agent 是 `Python-urllib/3.x`，肉眼可见的机器特征。
3. **HTTP/2**。curl 可能协商到了 h2，`urllib` 只有 h1.1。

这三条我一条都没验。要验得抓包、看握手、逐个改 header 试。

**我没验的原因是：验证成本大于绕过成本。**

## 工程决策：绕过，不修根因

判断用了四条：

- 这是一次性任务，不是长期服务
- 绕过只要二十行，修根因要抓包
- 不改任何对外契约，只改自己脚本的调用方式
- 出问题能立刻退回

四条都成立，就绕。

```python
cmd = ["curl.exe", "-s", "--max-time", "600", "-x", PROXY,
       "-X", "POST", "https://api.groq.com/openai/v1/audio/transcriptions",
       "-H", f"Authorization: Bearer {key}",
       "-F", f"file=@{path}",
       "-F", f"model={MODEL}", "-F", "language=zh",
       "-F", "response_format=verbose_json", "-F", "temperature=0",
       "-F", f"prompt={PROMPT}", "-o", out]
subprocess.run(cmd, check=True)
```

用 `subprocess` 有三个代价，都得处理：

- **引号转义**：Windows 上路径带空格会炸，用列表传参不要拼字符串
- **超时**：`--max-time` 必须给，不然一个卡住的请求会把整批拖死
- **返回码**：`check=True` 之外还要验返回内容是 JSON，代理返回的 HTML 错误页也会是 200

```python
if not raw.strip().startswith("{"):
    raise ValueError(raw[:200])
```

## 完整链路

1. `ffmpeg` 按 600 秒切片，`-vn -ac 1 -ar 16000 -b:a 64k`
2. 4 并发上传，每片最多重试 3 次
3. `verbose_json` 拿分段，按片偏移加上绝对时间戳
4. 合并、排序、输出 md

有两个细节值得单独说：

**一是 prompt 塞领域词表。** 这次是线性代数课，prompt 里直接写「奇异值分解、正交、特征值、酉矩阵、秩、列空间、零空间、低秩近似」。体感上专有名词准了不少——但**我没做对照实验，这是我的印象，不是数据**。

**二是空分段的兜底。** 有时候 `segments` 是空的，但 `text` 有内容。这时候直接把整片当一段，时间范围按片长算，不要丢。

## 数字

| 项 | 值 |
|---|---|
| 音频 | 77 分 53 秒，720×1584 竖屏，365 MB |
| 切片 | 8 片（600 秒/片） |
| 并发 | 4 |
| 结果 | 537 段，约 1.5 万字 |
| 转录耗时 | 约 3 分钟 |

## 能拿走的四条

1. **同一个请求在不同客户端表现不同，先怀疑客户端，别怀疑网络。** 网络问题通常两边都挂。
2. **端口别信配置，先验一次。** 一行 curl 的事。
3. **一次性任务，绕过优于修根因；长期服务，反过来。** 判据是「这个坑还会不会再来」。
4. **`check=True` 不够，还要验内容。** 代理的错误页也是 200。

## 结尾

我到现在也不知道那个 403 是 TLS 指纹还是 UA。

但脚本跑完了，1.5 万字在手上，后面的校对才是真活。

有些坑的根因，不值得挖。

## 素材缺口

- **403 的响应体**：当时没记录返回内容，所以分不清是网关拦还是 API 拒——这是全文唯一的硬缺口。
- **有没有试过 `requests`**：只记录了 `urllib` 失败，`requests` 是否同样 403 **未记录**。
- **根因**：TLS 指纹 / 默认 UA / HTTP/2 三个候选**一个都没验**，要验得抓包比对握手。
- **代理端口为什么换**：旧端口废弃的原因**未记录**，只知道配置没跟着改。
- **prompt 塞词表有没有用**：**没做对照实验**，正文那句话是印象，不是数据。
