# 设了全局代理，192.168.x.x 就连不上了：一次 502 加 30 秒超时

> 存档 ｜ 素材日期 2026-11-13 ～ 2026-11-18 ｜ 来源：个人实测记录
> 四问：AI 编得出吗？——编不出，502 和那组耗时是当场测的 ／ 有试错过程吗？——有，先怀疑登录、再怀疑服务、最后才怀疑代理 ／ 有数字或可复现报错吗？——有，10054、502、5–30 秒 ／ 半年后还有人踩吗？——会，每个装代理的人都要踩一次

---

## 现象

两个方向，同一台机器。

**程序不读代理。** Codex 桌面版远程控制连不上，日志一直报 `远程主机强迫关闭了一个现有的连接 (os error 10054)`，重试了 10 次。浏览器能登录，桌面版不行。

**程序读得太多。** 设好代理变量、上一个问题解决后，内网 `192.168.x.x:8xxx` 上的服务连不上了：

- `claude mcp list` 显示**连接失败**；
- 带代理访问局域网地址，返回 **502**——我们自己的服务从来不返回 502；
- 内网页面黑屏，十几个 JS 文件加载不完。

## 我以为是 X

先怀疑登录。素材里查出 `remote control requires ChatGPT authentication`，那是登录态被工具挪走了；修完登录，10054 还在。

再怀疑服务没起来。这个方向对了一半：有一次返回 `ECONNREFUSED`，查出来是服务只监听 `127.0.0.1`，"局域网无法访问"，跟代理无关。

最后怀疑平台。原话是"是不是应该新建一个 agent 进行"。不用，这些页面都在同一个域名下。

## 实际是 Y

代理只对公网有用。请求送进代理，代理访问不了内网，于是 502 或超时。

这台机器上的"代理"有三层，谁读哪一层不一样。

- **Windows 系统代理**：浏览器读，Codex 后台进程不读。所以直连 chatgpt.com 被重置，走代理返回 200。
- **`HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 环境变量**：命令行工具和 Codex 读，终端里的 npm、pip、git 也全走代理。
- **Clash 的分流规则**：走代理的流量还要再过一遍规则，规则不直连，照样 502。

## 怎么定位到的

对比直连和经代理。

| 访问方式 | 页面资源（JS） | 后端接口 |
|---|---|---|
| 直连 | 200，约 0.03 秒 | 401（没带登录，正常），约 0.04 秒 |
| 经代理 | 200，但要 **5–30 秒**，有一次卡到 30 秒超时 | 401，要 4–15 秒 |

同一地址，直连 0.03 秒，经代理 30 秒还超时——不是服务慢，是流量走错了路。

第二刀切在 `NO_PROXY`：加上内网地址后，`claude mcp list` 从**连接失败**变成**已连接**，因果就定了。

第三刀看 Clash 规则：订阅里只有一条 `MATCH,JMS`，全部流量转远端节点。加直连规则后复测，页面 JS 降到 0.017–0.037 秒，后端接口降到 0.02 秒。

## 修法 / 结论

Windows 下三条用户级变量：

```bash
setx HTTPS_PROXY http://127.0.0.1:7xxx
setx HTTP_PROXY http://127.0.0.1:7xxx
setx NO_PROXY "localhost,127.0.0.1,::1,192.168.0.0/16,172.0.0.0/8"
```

第一版只写了 `localhost,127.0.0.1,192.168.x.x`，被提醒"192.168 开头的都要不代理才行，还有 172 开头的"，才改成整段。

**五个容易写错的地方：**

1. **只关窗口不算重启。** 必须托盘右键退出或结束进程，否则"读不到新设的变量"。已打开的终端也一样。
2. **`172.*` 写宽了。** 内网只占 `172.16.*` 到 `172.31.*`，按"172 全排除"的代价是少数公网 172 地址也直连；精确写 `172.16.0.0/12`。
3. **CIDR 不是所有工具都认。** 支持 `/16`、`/8` 的有 Codex（Rust）和 curl 7.86 及以上，但"有些老工具只认精确匹配或域名后缀"。
4. **副作用要交代。** 对所有新启动的程序生效，"哪天代理软件没开，这些工具都会连不上网"。撤销：`reg delete "HKCU\Environment" /v HTTPS_PROXY /f`。
5. **Clash 规则要放在 `MATCH` 前面**，加的是 `- DOMAIN-SUFFIX,<域名>,DIRECT`，加完还要切订阅或重启才加载。

Claude Code 这边试了四种写法，只有一种有用：

- 配置目录放 `.env`：不读。
- `claude.json` 服务条目加 `env`：只对本地 stdio 服务生效，HTTP 服务只支持 `headers`。
- `settings.local.json` 的 `env` 块：是官方位置，但"shell 里已经有 `NO_PROXY` 时，这里写的值不会生效"，`claude mcp list` 和 `claude -p` 都连不上。
- 启动前 `export NO_PROXY="$NO_PROXY,<内网地址>"`：有效。

## 能拿走的 4 条

1. **连不上时，同一个请求直连一次、经代理一次。** 时间差和状态码差直接指向责任方。
2. **内网地址和 localhost 一开始就写进 `NO_PROXY`。** 别等踩了再补。
3. **502 不一定是服务端。** 本地代理会替服务端背这个锅。
4. **"设了环境变量"和"程序读到了"是两件事**，前者看注册表，后者看进程重启。
