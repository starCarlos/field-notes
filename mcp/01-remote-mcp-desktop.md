# 此 URL 没有服务器响应：远程 MCP 接 Claude 桌面版，先卡 9999 端口，再卡 Host 白名单

> 存档 ｜ 素材日期 2026-11-18 ｜ 来源：个人实测记录
> 四问：AI 编得出吗？编不出，`Invalid Host` 和端口限制都是现场抄的 ｜ 有试错过程吗？有，四轮 ｜ 有数字或可复现报错吗？有，401/403/405、9999、60 秒 ｜ 半年后还有人踩吗？会，Claude 远程连接器只认 443

## 现象

MCP 服务部署在测试机上，在 Claude 桌面版里加自定义连接器，填完地址点下一步，直接弹：

> 此 URL 没有服务器响应。请先检查该 URL 是否有拼写错误，然后再继续。

填的地址是 `https://mcp.example.com:9999/mcp/`。

## 我以为是 X

第一反应是 URL 写错了，或者末尾多了一个 `/`——报错文案自己就在说「检查拼写」。

第二反应是服务没起。但用 curl 请求，带 `/mcp/` 和不带斜杠的 `/mcp` 都返回 `401`，还带着 OAuth 发现地址；两个 `/.well-known/` 端点也都返回 `200`。服务是活的。

## 实际是 Y

**问题在 `:9999`，不在斜杠。** Claude 桌面版的远程自定义连接器由 Anthropic 云端发起请求，只支持标准 HTTPS 端口 `443`。本机能访问没用，点「仍要继续」也绕不过端口限制。

换到 443 之后，报错变了，但还没通：

```
403 Invalid Host: mcp-test.example.com
```

请求已经到达服务，但在进入 OAuth 之前就被 Host 校验拦了。这个 `403` 跟 Claude 里的 Client ID 没关系，改那个解决不了。

## 怎么定位到的

每步都有可复现的响应：

1. 打 `:9999`，拿到 `401` + `WWW-Authenticate`，证明服务在跑。
2. 打同域名的 `443`，证书链校验失败，证明公网入口没配好。
3. 换新域名后打 `POST /mcp`，返回 `403 Invalid Host`，证明卡在 Host 白名单，不是 OAuth。

修完 `403` 还有第三层：两个发现端点返回 `200`，但 JSON 里的 `resource`、`issuer` 和授权端点仍指向旧的 `:9999`。**接口还在告诉 Claude 去旧地址。**

## 修法 / 结论

**1. 公网入口走 443，证书链要完整。** 把 `/mcp`、两个 `/.well-known/` 发现端点和 OAuth 路由转发到现有服务。

**2. Host 白名单追加新域名。** 改部署进程实际加载的环境变量，不是改仓库里的文件：

```dotenv
MCP_ALLOWED_HOSTS=mcp.example.com,192.168.x.x,127.0.0.1,localhost,mcp-test.example.com
MCP_PUBLIC_URL=https://mcp-test.example.com/mcp
OAUTH_ISSUER=https://mcp-test.example.com
```

域名不带 `https://`，也不带 `/mcp`。不要为了省事关掉 Host 校验。

**3. OAuth 和 Bearer token 不要同时填。** Claude 里选「立即登录」+「使用您自己的 OAuth 客户端」，**请求标头全部留空**。授权完成后 Claude 自己会带 OAuth Bearer Token，手填 `Authorization` 或 `sk-****` 只会冲突。

**4. 验收顺序别搞反。** 先确认无 Token 的 `POST /mcp` 返回 `401` 而不是 `403`，且 `WWW-Authenticate` 指向新域名；再确认两个发现文档里没有旧域名。拿到 `401` 不代表登录通过。

## 顺带：50 秒这个数是怎么来的

有一类工具要等长回复，走 SSE 阻塞读取，原来上限 110 秒。三个默认值同时是 60 秒、彼此叠加：客户端 SDK 请求超时、反向代理读超时、调用方的工具超时。等待期间不发数据，60 秒以上先超时报错，而服务端任务其实还在跑——用户看到的是失败。

改法：只让这一类长等待工具走 SSE，其余工具继续回 JSON。服务端无状态，每个请求新建 transport，可以按请求切换响应模式，再加 `X-Accel-Buffering: no` 关掉代理缓冲。等待上限改成 5–50，默认 30。

但保活帧不会延长客户端超时，只有进度通知能，而那个开关默认是关的。所以 50 秒只是留余量，不是解决超时。调试时还踩到：进度异步发，任务完成太快时结果先写出、流就关了；1 秒节流的起点设成 0，刚启动不到 1 秒第一条进度就被节流掉，现在改成负无穷。

## 能拿走的 4 条

1. **「没有服务器响应」不一定是服务挂了。** 先分清「连不上」和「连上了但被拒」，`401` 和 `403` 是两回事。
2. **Claude 远程连接器从 Anthropic 云端发起，不是从你本机。** 必须公网可达，且只支持 IPv4。Codex 从本机连，没这个限制。
3. **换域名要同步四处：** Host 白名单、`MCP_PUBLIC_URL`、`OAUTH_ISSUER`、Java 侧的 `resource`。少一处就还是旧地址。
4. **远程服务器写进 `claude_desktop_config.json` 是不会连的。** 得在 Connectors 里加；会话里看不到就新开一个。
