# 174 处数字里删错 1 处：`<i class="icon icon-uniE00F">` 不是反爬，是站点把字弄丢了

> 存档 ｜ 素材日期 2026-11-11、2026-11-12 ｜ 来源：个人实测记录
> 四问：AI 编得出吗？编不出，`林立軒，765` 和 6 组码位反查都是逐条对出来的 / 有试错过程吗？有，先按正则一刀切，删完才发现丢数据 / 有数字或可复现报错吗？有，174 处、11 行 22 处、`i.icon` 数 = 0 / 半年后还有人踩吗？会，正则清噪声和「反爬」误判是抓取脚本的常见死法

## 现象

同一本书（732 章），两个看起来都像反爬的问题。

**第一个**：转简后用户说「很多数字…有对的有错的」。全书 174 处数字，105 处是段末数字，69 处是独立数字行。

**第二个**：用户问「为什么有 html 标签和代码」。全书 11 行 22 处 `<i class="icon icon-uniE00F"></i>`。

## 我以为是 X

数字：以为是站点塞的页尾锚点噪声，正则 `汉字+0`、`^\d+$` 一刀切，删干净就完事。

html 标签：以为是字体反爬。站点用自定义 icon 字体渲染个别汉字，浏览器里看得见、源码里是码位——很经典的套路。

## 实际是 Y

**数字：确实误删了 1 处合法数值。** 圣榜排名 `林立軒，765` 被当噪声删了。真相是站点把 `名。` 用空行拆到了下一段，原文应是 `林立軒，765名。」`。同类硬拆还有两处：`獲得30` + `%增強`、`肯定是256` + `個。」`。

**html 标签：不是反爬、不是编码错、不是自己脚本加的。** 抓第 366 章原始响应，拿到的是 `便像是水&lt;i class="icon icon-uniE00F"&gt;&lt;/i&gt;…融般。`——标签是**转义形式**。再用 Playwright 打开页面，按正文容器的元素 id 取节点，`i.icon` 元素数 = 0，`innerText` 原样显示这串代码。**读者在网站上看也是乱码。** 所以排除「字体反爬 / 图标渲染」。真相是源站用自定义 icon 字体渲染个别汉字，采集入库时整体转义成文本，字面信息就此丢失。

脚本侧的原因很具体：`extract_content` 里清标签正则 `<[^>]+>` 跑在 `unescape()` **之前**，匹配不到 `&lt;i …&gt;`；unescape 之后标签现形，已经没人清了。这是顺序 bug，不是漏写过滤。

## 怎么定位到的

数字这块，回备份逐条核 174 处，按「段末 `汉字+0`（87 处）/ 独立纯数字行（69 处）」分类。独立数字行里 52 处前段 `「` 未闭合——数字替换了右引号，能确认是噪声。剩下可疑的，看下一行是否接量词/单位。

html 这块靠三个指标一起看：真实浏览器取渲染后 DOM 的 `innerHTML` + `innerText` + `querySelectorAll('i.icon').length`。只有三个一起看，才能区分「标签被渲染成图形（反爬）」和「标签被当文本显示（数据损坏）」。两者修复思路完全相反。

## 修法 / 结论

**数字**：段末 `，N` 一律先看下一行是否接量词/单位（名、%、個…）。合法数值 `30%`(47)、`256个`(4)、`还差11%`、`0.5%`、`不低于1.5米` 全部保留。修复脚本改繁体原件后重跑整条转换链。

**html**：① `extract_content` 在 unescape 后加一次「icon 组回填 + 只按已知标签名清行内标签」（i/em/b/strong/span/font/p/div/u/sub/sup/img），避免误伤正文正常 `<>`；② 新增 `data/icon_map.json` 存码位组合 → 繁体原字，未知组合输出 `〔缺字:E00F,E03E〕` 而不是静默删除；③ 新增 `tools/fix_icon_residue.py`（`--dry-run` / `--map` / 自动 `.bak`）处理历史文件。

6 组码位反查（**推定，非原文**）：E00F,E03E=〔略〕｜E07F,E080=〔略〕｜E06C,E0F9=〔略〕｜E00E,E071=〔略〕｜E089,E023=〔略〕｜E06A,E039=〔略〕。依据是这些词在书里多处独立存在，11 处上下文全部通顺。**这批字原站就没有，无法从页面还原，只能靠上下文推定。**

## 能拿走的 4 条

1. 批量清理前先做「数字 + 后续段落」的全书扫描。别只按正则删——站点会把数值和单位用空行拆成两段。
2. 判断「网页上看到的是什么」不能只看 `response.text()`。必须用真实浏览器取 `innerHTML` + `innerText` + 选择器计数，三个一起看。
3. 抓取脚本里所有「实体还原」和「标签清理」的先后顺序都要审一遍。`unescape` 之后必须补一次清洗。
4. 静默删除未知标签 = 静默丢字。宁可留 `〔缺字:XXX〕` 可见标记，用户能看见才有机会补。

## 素材缺口

- 6 组码位对应的字是**上下文推定**，不是原文还原，原站已无此信息。可信度只能给到「11 处上下文通顺」。
- 面板文字 `小善：1` + `中善：1】`、`「6` + `」` 一类字符替换瑕疵**保留原样未处理**（数字没丢，合并会改写排版）。
- 同文件另有 4 个 `□` 是转简时生僻字转换失败残留（伤□ / 火山口 / 陨山），本轮未处理。
- `.tmp/` 下 14 个历史备份仍含同样标签，未动。
- 用户若指的是别的具体数值，需要章号或原句再按处修——目前只知道这一处。
